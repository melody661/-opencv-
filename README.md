### -opencv-
#####实现思路

***1.先把图转为hsv，以便于色、饱和度、亮度分开调参，更有利于分离出白光、假色等噪点，然后按照设定参数将原图符合区域扣到二进图上，每个连通块存于vector contours中。2.用旋转矩形定义每个contours[i]，方便取每个矩形的点和长度。***
****在这里就要实现第一个目标，用Pts[n][4]依次存储左上左下右下右上四个点****
***在实测中发现，旋转矩形的四个点的方位定义会随着旋转角度不同而改变，为统一规定，我写了GYH这个函数去统一：规则；最左边的点默认是左上点，同x值，取y小的一点；同y值，取x小的点（其它点判断同理）***
***3.匹配合法矩形，用两层for循环加上平行条件以及垂直条件去筛选合法的矩形对***
***4.对于每个合法的矩形对进行画图即完成识别装甲板的目标***

*****遇到困难*****

***1.由于视角不同、相机取参等种种原因，得到的矩形在黑白图中不稳定，这导致写平行条件的时候，其合理误差的规定很困难（我捣鼓了很久，已红）***

***2.由于时间不是很充裕，写的这个版本没有识别中间白色以及具体数字的功能，我认为在理论上这会导致完全平行的两个装甲板其灯条判断很容易出现失误***

*****解决问题时的心路经历*****

***（真的很想用ai写一些判定条件，但是ai写的东西对于学习这部分知识的益处不大，所以我只用ai查询相应模块，分析思路合理性。）***

***所以在解决平行条件判断合法矩形对这一块，由于合法误差难写，导致解决这块问题时我有很多想法，但是每一种想法有自己的优势也有自己的不足（甚至有些缺点是致命的，比如我想当然认为判断其平行只需用旋转矩形自带的角度，相减不超过合法误差即可，但是旋转矩形对于angle的定义是镜面的，导致矩形垂直时角度直接翻转而无法判定），这时我又想着去用别的思路，直到最后我选择用垂直＋长度判定的时，这期间的思路很凌乱，让我很崩溃。***


*****未来改进思路*****

***也正如在遇到困难所说，以后的方向是将装甲板中心的白色数字加入到合法矩形对的判定条件中，以便于更好判断像两个装甲板完全平行的情况，其次，根据数字不同，应写几个类把它们区分开，为后续的路径预判等更高级的项目做好基础***
